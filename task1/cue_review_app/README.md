# Cue-conflict review GUI

This local browser app records blind, resumable approval decisions for the
cue-conflict candidates generated by `task1.ipynb`. It deliberately exposes no
model predictions.

Approval rubric: approve only when the content object remains recognizable,
the transferred texture is visibly present, and there is no severe smearing,
collapse, clipping, or decoder artifact.

After running the notebook's candidate-generation cell:

```bash
python task1/cue_review_app/app.py
```

Open <http://127.0.0.1:8765>. Decisions are saved immediately under
`task1/results/cue_conflict_candidates/review_ratings.json`. Once every bucket
has at least 20 approvals, click **Export balanced approved manifest**. The app
uses a stable seed-derived ordering to select exactly 20 approved images from
each of the ten pair-direction buckets and writes the 200-row
`task1/results/cue_conflict_approved_manifest.csv` consumed by the notebook.

Useful options:

```bash
python task1/cue_review_app/app.py --port 9000 --quota 20
```

If a bucket cannot reach its quota, append new candidates without replacing
any existing candidates or ratings:

```bash
python task1/cue_review_app/generate_supplement.py
```

By default this finds every bucket below 20 approvals and appends 40 new unique
candidates to each deficient bucket. Stop and restart the GUI afterward so it
reloads the expanded manifest, select **Unreviewed**, and continue under the
same rubric. Repeated runs are safe: existing content/style/direction IDs are
excluded. Never use model predictions to approve or reject candidates.
